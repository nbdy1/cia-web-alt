# CDS untuk Guru — Android app

A thin native shell (Capacitor 8) around the live website. **One app for every
school**: it opens `https://characterdev.systems`, the user logs in, and the site
sends them to their school's subdomain (`slug.characterdev.systems`) exactly as it
does in a browser. Because it loads the live site, **web changes reach the app
instantly**; you only publish a new app version when something in `native/` changes.

```
native/
  capacitor.config.json   app id, start URL, allowed domains, user-agent tag
  www/offline.html        shown when the phone has no connection (server.errorPath)
  assets/                 logo sources used to generate launcher icon + splash
  android/                the Android Studio project (generated by Capacitor, committed)
```

## What the web app does differently inside the app
The app tags its user agent with `CDSApp/1.0` (`lib/native.ts`), and the site adapts:

| Area | In the app |
|---|---|
| Launch | Anonymous users go to **login**, not the marketing page. |
| Voice input | Android WebView has no Web Speech API, so voice is recorded and transcribed with **Whisper** (CDS + BK assessments). Microphone permission is asked on first use. |
| Printing | The print buttons (CDS rapor, BK monthly rapor) are hidden — WebView cannot print. Printing stays available on the website. |
| Notifications | Browser notifications/service workers don't run in WebView; the in-page reminder cards still work. Reminders while the app is closed need native push (see "Not done yet"). |
| External links | WhatsApp, Instagram etc. open in the system browser; only `characterdev.systems` and `*.characterdev.systems` stay in the app. |

## Requirements (one-time)
- **Android Studio** (includes the Android SDK and a compatible JDK). The JDK 25 that happens to be on this Mac is too new for Android Gradle; use Android Studio's bundled JDK.
- Node 22+ (already used by the project).

## Build and run on a phone
```bash
cd native
npm install
npx cap sync android        # copies capacitor.config.json + plugins into android/
npx cap open android        # opens Android Studio
```
In Android Studio: connect a phone (USB debugging on) or start an emulator, press **Run**.

### Test against a local/staging server instead of production
Edit `server.url` in `capacitor.config.json` (for example your Mac's LAN address) and, **only for that test**, add `"cleartext": true` for plain `http://`. Run `npx cap sync android`, rebuild, and **revert before releasing**. Note the site's cookies/tenant logic expect the real domain, so production or a real staging domain is the faithful test.

## Release to Google Play
1. **Developer account**: Play Console, one-time US$25. A personal account created recently may have to run a **closed test (about 12 testers for 14 days)** before production access; an organization account is exempt. Check the current Play rules.
2. **Version**: in `android/app/build.gradle` raise `versionCode` (a whole number that must increase with every upload) and `versionName`.
3. **Signing key** (do this once and **back it up**; losing it is painful):
   ```bash
   keytool -genkey -v -keystore ~/cds-upload-key.jks -keyalg RSA -keysize 2048 -validity 10000 -alias cds-upload
   ```
   Keep it **outside the repo** (`*.jks`, `*.keystore`, `keystore.properties` are git-ignored anyway). Use **Play App Signing** (the default): you upload with this "upload key" and Google holds the real signing key.
4. **Build the bundle**: Android Studio -> *Build -> Generate Signed Bundle / APK -> Android App Bundle (.aab)* using the key above.
5. **Play Console** -> create the app -> upload the `.aab` to *Internal testing* first -> add testers -> then promote to *Closed/Production*.

### What Play will ask for
- **Privacy policy URL** (required). This app handles information about minors (students, counselling notes), so the policy needs to be accurate and reviewed by the school/organization. A policy page does not exist on the site yet.
- **Data safety form**: data collected = account info (name/email), user-generated content (reports, counselling notes), audio (voice input, sent for transcription), photos (student photos). Data is encrypted in transit; say whether users can request deletion.
- **Permissions in the manifest**: INTERNET, RECORD_AUDIO, MODIFY_AUDIO_SETTINGS, CAMERA (optional hardware). Be ready to explain each (voice input, student photos).
- **Content rating, target audience**: the users are teachers, not children.
- **Store listing**: a **512x512 icon**, a **1024x500 feature graphic**, and at least 2 phone screenshots.
- **Account deletion**: accounts are created by admins, so in-app sign-up does not exist; still confirm what Play expects for your case.

## Known limitations
- **Needs internet.** No offline mode; without a connection users see `www/offline.html` and it retries automatically when the phone is back online.
- **No printing/PDF** from inside the app (see table above).
- **Logo quality**: `app/icon.png` is only 512px and soft. The launcher icon and splash were generated from it and are fine for testing, but provide a **1024px logo (ideally vector)** for the Play Store listing, then replace `assets/icon-only.png`, `assets/icon-foreground.png`, `assets/splash.png` and run `npm run assets`.
- The status bar follows the system theme; it does not take each school's brand colour.
